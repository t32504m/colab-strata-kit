対象: Colab の Strata で動く Qwen3.8 に、コード生成・調査・繰り返しの仕事をさせたいセッション（Claude Code など）。
このファイルは入口。手順・注意・判断の要点はここにすべて書き、詳しい資料は最後に挙げる。
最終更新: 2026-11-12。
**ほかの PC（配布用の zip から入れた場合）**: このファイルの `G:\local` は、キットを置いたフォルダ（`colab-strata-kit`）に読み替える。作業ツリーの置き場は、そのドライブの直下の `delegate-runs`。

ユーザーがこのファイルを渡すときの一言の例:

## 1. 全体像
- **ワーカー**: Qwen3.8-Flash-Next IQ3_S（262144 トークンの文脈、画像入力あり）。Colab の A100 で Strata というエンジンが動かし、手元の `http://127.0.0.1:8080` に SSH の転送で出ている。
- **使い方は2つ**。
  - **A. 委譲**: `delegate`（delegate.ps1）で、カード1枚の仕事を DeepSeek Harness（dsh）の headless に渡す。ワーカーは git の作業ツリーの中でファイルを読み書きし、テストを実行する。終わると検証・受け入れテストの結果と差分がまとまる。コードの変更、ファイルを読む調査、棚卸しに使う。
  - **B. API を直接呼ぶ**: OpenAI 互換・Anthropic 互換の API。ファイル操作の要らない、短い問い合わせを大量に流す仕事（分類、抽出、変換、要約の下書き）に使う。
- **あなた（監督）の役目**: 判断・設計・レビューとユーザーとのやりとり。ワーカーには判断の要らない量の仕事だけを渡し、結果は自分の決めた方法で確かめる。

## 2. 前提: Strata が動いているか
```powershell
Invoke-RestMethod http://127.0.0.1:8080/health -TimeoutSec 5   # "loaded": true なら使える
```
- **応答が無い**: ランタイムが止まっている。いちばん良いのは、ユーザーに **Colab Manager**（`G:\local\Colab Manager.lnk`）で「起動」を押してもらうこと。準備完了まで約8分。委譲（A）なら、delegate が自分で起動を頼んで待つ（Manager が開いていればそれに、無ければ開く）。
- **費用**: ランタイムが動いている間、約 6.7 CU/時かかる（使っていなくても）。Manager は、30分使われないと自動で止める。
- **止め方の決まり**:
  - ユーザーが Manager で起動したランタイムは、ユーザーのもの。**あなたは止めない**（dsh の作業中かもしれない）。
  - あなたが試験のために `bridge.sh start` で起動したランタイムは、終わったら止めて確かめる。手順は `G:\local\CLAUDE.md` の「実機テスト（Colab）の決まり」（止めたあと `bridge.sh status` で `MANAGER_STATE=absent` と `Active assignments: 0`、費用を `G:\local\colab-manager\HANDOFF.md` に記録）。
- **「Connection error」が出たとき**: まず上の health を見る。応答が無ければ、ランタイムが止まっているか、トンネルを張り直している最中（接続が切れても十数秒で自動で戻る）。
- **やってはいけないこと**: SSH の共有接続やトンネルのプロセスを殺す、`bridge.sh reconnect` / `restart` / `stop` を、ユーザーのランタイムに断りなく使う。2026-11-09 に、切断の試験からユーザーのランタイムを失った。

## 3. A. 委譲（delegate）

### 任せるかどうか（作業の前に毎回）
1. 監督にしかできないこと（設計、仕様の解釈、ユーザーとのやりとり、原因の分からない不具合、秘密・外部への送信・費用・取り返しのつかない操作）は任せない。
2. **結果をすぐ使うものは任せない**。ワーカーは1件に2〜7分かかり、止まっていれば起動に約8分かかる。
3. 渡せる形にできるものだけ任せる: やることが決まっている、できたかを機械で判定できる、変更してよいファイルを列挙できる。
4. 割に合うものだけ任せる。目安: **出力か読む量が、カードの10倍以上なら任せる**。数行の修正は自分でやる。
5. 振り分けと理由を台帳 `G:\local\delegation\ledger.md` に1行書く（例: `| 2026-11-10 | G-sound-1 | 任せる | 逆コンパイル結果 4万行を読む調査。出力が大きい |`）。

任せてよい仕事の例: テストを厚くする、同じ形の繰り返し（多数ファイルの置き換え・形式の変換）、読む量の多い調査（ログ・逆コンパイル結果を読んで、根拠付きの表にする）、棚卸し（アセットの一覧と分類）、何度も回す仕事（数千回のテスト・総当たり）。

### 手順
呼び方は `G:\local\delegation\delegate.cmd <コマンド> ...`。Claude Code では **PowerShell ツールから呼ぶ**（Bash ツールから引用符つきの引数を渡すと崩れる）。
1. **カード**を `G:\local\delegation\cards\<ID>.md` に書く（下の雛形）。判断はすべてカードの中で済ませる。
2. **受け入れテスト**（コードの仕事のとき）を `G:\local\delegation\accept\<名前>\` の下に、対象リポジトリと同じフォルダ構成で書く。ワーカーには見せず、終わった後に置いて実行し、すぐ消す。3〜8件、ワーカーが見落としそうな所だけを狙う。前提の操作（データを作る、サブコマンドを呼ぶ）も戻り値を assert する。カードに書いていない仕様はテストしない。
3. `delegate precheck -Card cards\<ID>.md` で、今のコードに受け入れテストを流し、落ち方を見る（まだ無い機能の不在で落ちるのは正しい。準備の失敗や書き間違いで落ちていたら直す）。
4. `delegate run -Card cards\<ID>.md -Async` で渡す（すぐ戻る）。続けて `delegate wait -Run <ID>` を **run_in_background** で動かし、待たずに自分の仕事を続ける。まとめて流すなら `queue\` にカードを置いて `delegate queue -Parallel 2`。
5. 終わったら `G:\local\delegation\runs\<実行>\report.md` **だけ**を読む（状態、範囲外の変更、検証と受け入れの結果、ワーカーの要確認）。
6. 確かめる: 差分（diff.patch）のうち**テストの削除行**（前のテストを弱めていないか）と、受け入れテストが届かない部分（並行処理、セキュリティ）だけを読む。調査なら、表の行を3つ選んで根拠を実際に開く。ワーカーの「できました」は根拠にしない。
7. 決める:
   - `delegate adopt -Run <実行> [-Message "<件名>"]`: 採用。squash merge してコミットし、作業ツリーとブランチ、差し戻し元も片付ける。対象リポジトリに未コミットの変更があると断る。
   - `delegate followup -Run <実行> -Note "<指示>" [-Async]`: 差し戻し。前回のブランチの上で、前回の要確認と失敗を引き継ぐ。**2回まで**。3回目は自分で引き取る。
   - `delegate discard -Run <実行>`: 破棄。
- `delegate status` で最近の実行の一覧が見られる。`<実行>` は `runs\` の下のフォルダ名か、その先頭（`T-001` なら最新）。

### カードの雛形
```
タスクID: <英数字と . _ ->
対象リポジトリ: <git リポジトリのパス>
目的（なぜ）: <1〜2文。ワーカーが迷ったときの拠り所>
入力（読むファイル・資料）: <パス>
出力: <調査・棚卸しなら出力するファイル。コードなら書かない>
変更してよいファイル: <パス（カンマ区切り）>
やること（判断の余地を残さない）:
- <名前・型・例外・並び順・境界の扱い・出力の形を全部決めて書く>
完了条件（コマンドで判定）: 検証コマンドと受け入れコマンドが成功する。
検証コマンド: <ワーカーにも見える検証。テストの実行、check_report.py など>
受け入れテスト: <accept\ の下のフォルダ名>
受け入れコマンド: <受け入れテストを実行するコマンド>
やってはいけないこと: <外部パッケージ、範囲外の変更、前のテストを弱める>
不明点が出たら: 決めずに「要確認」として返す
```
調査の仕事の検証コマンドには、レポートの形を判定する `python G:\local\delegation\tools\check_report.py <レポート> --heading "<見出し>" --table-columns "列1|列2|根拠" --min-rows <N> --evidence` を書く。

### 状態の意味
| 状態 | 意味 | 次の操作 |
|---|---|---|
| ready_for_review | 範囲内で、検証と受け入れテストが通った | 上の6を見て adopt |
| accept_failed | 受け入れテストに落ちた | 失敗の出力を見て followup（テストの中身は渡さず、直す点を言葉で） |
| verify_failed | カードの検証コマンドが通らない | followup（失敗の出力は自動で引き継がれる） |
| out_of_scope | 変更してよいファイル以外を変えた | カードの範囲を見直す |
| no_change | 何も変えなかった | worker-report.md を読む（要確認で止まっていることが多い） |
| worker_error / timeout | 異常終了・時間切れ（既定40分） | 仕事を小さく分ける |
| error: ... | 準備の段階で失敗（リポジトリが無いなど） | 理由のとおり直す |

### ワーカーの性質（試験で分かったこと）
- コードは読みやすく、カードに忠実。決めていないことは決めずに「要確認」として返す（毎回3〜7項目、多くはカードの書き漏れ）。
- 自分のテストは自分の想定どおりにしか書かない。1回目は、環境（Windows の cp932 の出力）・現実のデータの乱れ・並行処理の不具合が残りがちだった。そこを受け入れテストで突く。
- 前のテストを勝手に弱めたことはない（それでも削除行は見る）。
- ワーカーの作業ツリーの中では git が動かない（サンドボックスの制限）。差分は delegate が取る。
- 1回の出力は最大 32768 トークン。巨大なファイルを1回で書かせると途中で切れるので、カードで「大きなファイルは分けて書く」か、仕事を分ける。

## 4. B. API を直接呼ぶ
| 項目 | 値 |
|---|---|
| OpenAI 互換 | `http://127.0.0.1:8080/v1`（`/v1/chat/completions`） |
| Anthropic 互換 | `http://127.0.0.1:8080/v1/messages` |
| モデル名 | `qwen3.8-flash-next-iq3_s`（`/health` の `model` が正） |
| API キー | 設定なし。どんな文字列でも通る |
| 文脈 | 262144 トークン（`/health` の `max_context`） |
| 出力の上限 | `max_tokens` は 32768 まで（文脈の残りを超えると Strata が自動で縮める） |
| 速さ（実測） | 生成 約86 トークン/秒。未読のプロンプトの読み込み 約10万トークンで36〜208秒（ディスクのキャッシュ次第） |
| 同時実行 | エンジンは1つ。2〜3本まで。それ以上は順番待ちになるだけ |

- **考える過程（thinking）が既定で出る**。`max_tokens` の大半を考えるのに使い、答えが空のまま上限に達することがある（エンジンのログに「reached max tokens while still thinking」）。Strata は既定で考える量を `max_tokens` の75%に抑える（32768 なら 24576）。短い答えが欲しい仕事では、リクエストに `reasoning_budget_tokens` を付けて考える量を小さくする。考えるのを完全に止める方法は未確認。
- 大量に流すときは、結果をファイルに書き、件数と形を機械で確かめる（委譲の check_report.py の考え方と同じ）。1件ずつの中身は抜き取りで見る。
- 例（Python、標準ライブラリだけ）:
```python
import json, urllib.request
req = urllib.request.Request("http://127.0.0.1:8080/v1/chat/completions",
    data=json.dumps({"model": "qwen3.8-flash-next-iq3_s", "max_tokens": 4096,
                     "messages": [{"role": "user", "content": "..."}]}).encode(),
    headers={"Content-Type": "application/json", "Authorization": "Bearer x"})
print(json.load(urllib.request.urlopen(req, timeout=600))["choices"][0]["message"]["content"])
```

## 5. つまずきやすい所
- **Claude Code の Bash ツール（Git Bash）**: `delegate.cmd` に引用符つきの引数を渡すと崩れるので、PowerShell ツールを使う。WSL のパスを渡すときは `MSYS_NO_PATHCONV=1` を付ける。
- **PowerShell 7**: delegate.ps1 は 7 以上が要る。delegate.cmd が探して使う（Codex に同梱の pwsh、`C:\Program Files\PowerShell\7\pwsh.exe`、PATH の pwsh の順）。
- **作業ツリーの置き場**: `G:\delegate-runs`（`DELEGATE_WT_ROOT` で変える）。dsh のサンドボックスが作業フォルダのアクセス権を書き換えるので、置き場には自分のフル コントロールが要る（delegate が初めて作るときに付ける）。この PC のほかのアカウントからも読めるので、**秘密を含むリポジトリは渡さない**。
- **対象リポジトリ**: git リポジトリであること。adopt の前に、自分の未コミットの変更を片付けておく。
- **秘密の値**: `G:\local\strata-colab-cli\config.local.env` などのトークンは表示しない・ワーカーに読ませない。値はユーザーが書く。
- **受け入れテストの中から `node --test` を呼ぶとき**: 子のプロセスの環境から `NODE_TEST_CONTEXT` を消す（`const env = { ...process.env }; delete env.NODE_TEST_CONTEXT;` を spawnSync に渡す）。消さないと、子は親の試験の一部として動き、失敗しても終わりの番号が 0 になる（2026-11-10、壊したコードで落ちるかを見る受け入れが、全て「落ちない」と誤って出た）。
- **Node の依存物**: 作業ツリーは git の中身だけで、`node_modules` が無い。`G:\delegate-runs\node_modules` に対象リポジトリの `node_modules` へのジャンクションを置くと、Node が親のフォルダを探して見つける（2026-11-10、parking-gas の Playwright で使えた）。
- **文字コード**: ワーカーに書かせる Python の CLI は、標準出力を UTF-8 にさせる（Windows の cp932 では絵文字や一部の日本語で落ちる）。受け入れテストで `PYTHONIOENCODING` を外して確かめる。

## 6. 終わり方
- 委譲の結果を採用・破棄したら、台帳に結果が残っているか見る（delegate が自動で書く）。
- 変更を検証したらコミットする（このユーザーの希望。push は頼まれたときだけ）。
- 自分で起動したランタイムは止めて、費用を記録する（2を参照）。ユーザーのランタイムは止めない。
